## وصف الأفكار الإضافية

### 11. مخطط الإمداد الإنساني

يدير المستخدم مخازن وطرق نقل واحتياجات مناطق متعددة بعد أزمة. عليه توزيع الغذاء والدواء والفرق ضمن ميزانية ووقت محدودين. يستخدم قوائم الأولوية، تخصيص الموارد، المسارات، الفرز، وسجل القرارات.

### 12. مختبر تتبع انتشار وبائي تعليمي

محاكاة تعليمية غير طبية تُظهر أثر الاتصال والعزل والتطعيم الافتراضي على شبكة سكانية. يختبر المستخدم سياسات مختلفة ويقارن المنحنيات والتكلفة والأثر، باستخدام الرسوم والحالة والمراحل والعشوائية المضبوطة.

## أفضل ثلاثة Prototypes

### 1. مختبر الخوارزميات المرئي

**سبب الاختيار:** أعلى قيمة تعليمية وأقل مخاطرة تقنية، ويكشف مبكرًا قدرة `skui` على Canvas والتحريك والتحكم في السرعة والمقارنة.

**المشاهد:**

1. شاشة اختيار الخوارزمية ومجموعة البيانات.
2. مساحة عمل بملء الشاشة: Canvas رئيسي، شريط خطوات، عداد مقارنات وتبديلات، تحكم بالسرعة.
3. وضع مقارنة جنبًا إلى جنب بين خوارزميتين.
4. تقرير نهائي يشرح عدد العمليات وBig-O ويوصي بالخوارزمية الأنسب.

**معيار نجاح النموذج:** تشغيل Linear/Binary Search وBubble/Selection/Insertion Sort خطوة بخطوة، إيقاف/استئناف/إعادة، دون فقدان الحالة.

### 2. غرفة الألغاز المشفرة

**سبب الاختيار:** تجربة قصصية متعددة المشاهد، تستفيد من تدريبات قيصر وأنظمة العد والبحث وتحولها إلى منتج مترابط.

**المشاهد:**

1. Briefing قصصي واختيار مستوى الصعوبة.
2. خريطة غرفة بها 4 محطات مقفلة.
3. محطة قيصر، محطة ثنائي/ASCII، محطة نمط منطقي، محطة بحث.
4. لوحة مخزون للمفاتيح والتلميحات.
5. شاشة هروب بنتيجة محسوبة من الوقت والدقة والتلميحات.

**معيار نجاح النموذج:** سيناريو كامل قابل للإنهاء، تلميحات محدودة، حفظ المرحلة داخل الجلسة، وإعادة توليد بعض القيم.

### 3. غرفة عمليات المدينة الذكية

**سبب الاختيار:** يختبر أعلى مستوى من إدارة الحالة والقرارات والموارد، ويقدم نموذجًا قويًا لمنتج موهبة قابل للعرض.

**المشاهد:**

1. Briefing للمدينة والموارد ومعيار النجاح.
2. خريطة قطاعات مع مؤشرات المرور والطاقة والصحة والسلامة.
3. Timeline لتنبيهات متزامنة وبطاقات قرارات.
4. لوحة تخصيص فرق وميزانية ووقت.
5. تقرير بعد كل جولة، ثم تقرير نهائي يفسر الاستقرار والرضا والكلفة.

**معيار نجاح النموذج:** ثلاث جولات متغيرة، أحداث مترابطة، قرارات ذات trade-offs، ونتيجة قابلة للتحسين.

## Wireframes النصية


## المكونات المطلوبة قبل بناء النماذج

### أولوية P0

- `Scene` وScene state machine.
- `GameBoard` و`MapPanel`.
- `MetricCard` و`StatusPanel`.
- `Timeline` و`MissionCard`.
- `StepIndicator` و`LevelBadge`.
- `Dialog` و`Toast`.
- Canvas API: خطوط، دوائر، صور، مسح جزئي، نص RTL، hit testing، keyboard/pointer.
- عقد Callback موحدة تدعم callbacks دون معامل أو بمعامل.
- Fullscreen/auto-height layout دون تمرير متداخل.

### أولوية P1

- `HeroSection`, `ProgressRing`, `AnimatedCounter`.
- `DataGrid`, `Tooltip`, `Drawer`.
- `CharacterGuide` سياقي بدل Guide ثابت.
- انتقالات حالات خفيفة واحترام `prefers-reduced-motion`.

### أولوية P2

- أصوات اختيارية محلية مع mute.
- حفظ/استعادة جلسة المشروع.
- Theme tokens مستقلة لكل مشروع.

## خطة التنفيذ بعد الموافقة

1. تثبيت عقد Runtime والأحداث وإغلاق الأخطاء الحرجة.
2. إضافة P0 فقط مع اختبارات مستقلة.
3. بناء Design spec منفصل لكل Prototype.
4. تنفيذ مختبر الخوارزميات أولًا بوصفه اختبار قدرة المنصة.
5. تنفيذ غرفة الألغاز ثم غرفة عمليات المدينة.
6. مراجعة داخلية وRubric لكل مشروع.
7. عرض تقرير النتائج؛ لا يبدأ المشروع الرابع قبل الموافقة.
