# مصفوفة QA لتصدير مشروعات skui

## المبدأ

يجب أن تستخدم جميع البيئات المصدر نفسه لـ:

- Skulpt runtime.
- مكتبة `skui` وevent bridge.
- CSS وtheme tokens.
- الأصول المحلية.
- منطق snapshot والحالة.
- حدود التنفيذ ورسائل الأخطاء.

أي اختلاف Runtime بين المنصة والحزمة المصدرة يُعد عيبًا حرجًا.

## الحالة الحالية الصريحة

| الهدف | الحالة | قرار الجودة |
|---|---|---|
| معاينة المنصة | متاح | يحتاج سيناريو كامل لكل مشروع |
| WebApp مباشر | متاح | يحتاج سيناريو كامل لكل مشروع |
| WebApp ZIP | متاح | الاختبار الحالي محدود بfixture واحد |
| PWA | الواجهة معطلة/قيد التطوير | لا يُعلن كمدعوم |
| Windows | خط بناء جزئي وغير متحقق تثبيتيًا | لا يُعلن كمدعوم |

## اختبارات ZIP

1. توليد ZIP من المشروع الحقيقي، لا fixture مبسط فقط.
2. فحص وجود runtime وstdlib وstyles وassets وbuild metadata.
3. خدمته من HTTP محلي.
4. تنفيذ السيناريو الأساسي والخاطئ.
5. قطع الاتصال بالشبكة وإعادة التشغيل.
6. مقارنة إصدار Runtime مع إصدار المنصة.
7. التحقق من عدم تضمين حل المعلم أو بيانات حساسة.

## اختبارات PWA عند تفعيلها

- Manifest صالح وأيقونات صحيحة.
- Service worker يخزن جميع الأصول المحلية.
- تثبيت فعلي على Android/Desktop.
- تشغيل offline بعد إغلاق المتصفح.
- تحديث إصدار دون cache قديم.
- عدم فقد الحالة أو تعليق worker.

## اختبارات Windows عند تفعيلها

- نجاح CI artifact والتحقق من hash.
- تثبيت على Windows نظيف.
- تشغيل دون Node أو Python مثبتين.
- إعادة تشغيل التطبيق وحفظ البيانات المعلن عنها.
- uninstall نظيف.
- توثيق حالة التوقيع وSmartScreen بصدق.

## بوابة الاعتماد

- في المرحلة الحالية: نجاح المنصة وWebApp وZIP إلزامي.
- PWA وWindows يسجلان `not available` ولا يمنحان ادعاء دعم.
- عند تفعيل أي هدف يصبح اجتياز مصفوفتِه إلزاميًا للإصدارات التالية.
- لا يُعتمد المشروع إذا اختلف سلوكه أو تصميمه جوهريًا بين المنصة والتصدير.
