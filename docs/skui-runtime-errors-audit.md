# تدقيق أخطاء Runtime لمشروعات skui

**تاريخ التدقيق:** 2026-07-13  
**قاعدة الإطلاق:** أي مشروع ينتج خطأ Runtime في مسار مستخدم يُوسم `blocked` ولا يظهر للطلاب حتى الإصلاح وإعادة الاختبار.

## الأخطاء المؤكدة

### المؤقت — `blocked`

```text
TypeError: tick() missing 1 required argument: count
```

- الحدث: `Timer.on_change`.
- الكود يعرّف `tick(count)`.
- جسر الأحداث استدعى الدالة دون القيمة.
- الاختبار الحالي يضغط «تشغيل» لكنه لا ينتظر نبضة Timer ولا يتحقق من استمرار العد دون خطأ.

### تطبيق الألوان — `blocked`

```text
TypeError: update() missing 1 required argument: value
```

- الحدث: `Slider.on_input`.
- الكود يعرّف `update(value)`.
- اختبار الـ 13 مشروعًا لا يتفاعل مع منزلقات الألوان، ولذلك لم يكتشف العطل.

## السبب النظامي

المشكلة ليست في المشروعين فقط؛ عقد Callback في Runtime غير مثبت باختبار قبول كافٍ:

- `workerSource` يحاول استنتاج عدد معاملات دالة Skulpt من خصائص داخلية.
- هذا الاستنتاج لا يعمل بصورة موثوقة لكل الدوال والـ closures والـ bound methods.
- عند فشل الاستنتاج تُستدعى بعض أحداث القيمة دون معامل.
- الأحداث المتأثرة المحتملة: `on_change`, `on_input`, `on_select`, `on_submit`, `on_key_press`, وTimer.

يجب استبدال الاعتماد على الاستنتاج الهش بعقد حدث موحد وموثق، مع توافق صريح مع:

```python
def callback():
    ...

def callback(value):
    ...
```

إضافة إلى ذلك، أحداث Canvas ليست آمنة للتوسع الحالي: `pointerdown` يرسل إحداثيات
لكن `on_click` لا يمرّر قيمة إلى Python، بينما كائن الإحداثيات في `on_input` يتحول
إلى النص `"[object Object]"`. لذلك لا يجوز اعتماد مشروع Canvas متقدم قبل تعريف
payload منظم للإحداثيات واختباره.

## حالة المشروعات الحالية

| المشروع | التصنيف | حالة Runtime الحالية | قرار العرض |
|---|---|---|---|
| تخمين الرقم | تدريب مصغر | مسار أساسي مختبر؛ يحتاج حواف وإعادة طويلة | training/qa |
| آلة حاسبة | تدريب مصغر | العمليات الأساسية مختبرة | training/qa |
| نموذج تسجيل | تدريب مصغر | تحقق سلبي مختبر جزئيًا | training/qa |
| قائمة مهام | تدريب مصغر | إضافة مختبرة؛ بقية الفلاتر والحذف غير مكتملة | training/qa |
| اختبار قصير | تدريب مصغر | خطوة واحدة فقط مختبرة | training/qa |
| مؤقت | تدريب مصغر | خطأ Callback مؤكد | blocked |
| لوحة بيانات بسيطة | تدريب مصغر | تحديث واحد مختبر | training/qa |
| تطبيق ألوان | تدريب مصغر | خطأ Callback مؤكد | blocked |
| لعبة Canvas المصغرة | تدريب مصغر | زر حركة فقط؛ pointer/keyboard غير مختبرين | training/qa |
| البحث الخطي | تدريب/نواة قابلة للتطوير | نجاح بحث مختبر؛ الفشل والتحقق ناقصان | training/qa |
| تشفير قيصر | تدريب/نواة قابلة للتطوير | تشفير فقط مختبر جزئيًا | training/qa |
| لعبة الحساب | تدريب مصغر | سيناريو خطأ واحد مختبر | training/qa |
| تحويل أنظمة العد | تدريب مصغر | إدخال غير صالح مختبر؛ الحالات الأخرى ناقصة | training/qa |

`training/qa` لا تعني صالحًا كمشروع نهائي، بل يعني أن التدريب يحتاج إكمال مصفوفة القبول قبل نشره الواسع.

## فجوات الاختبارات الحالية

- يوجد 14 اختبار E2E في الملف الحالي، لكن معظمها smoke أو اختبارات بنية مشتركة.
- الاختبار الجامع ينفذ فعلًا أساسيًا واحدًا فقط لكل مشروع.
- المؤقت لا يُنتظر حتى Timer callback.
- الألوان لا تُحرّك منزلقاتها.
- الاختبار القصير لا يصل إلى النتيجة ولا يعيد المحاولة.
- قائمة المهام لا تختبر الإتمام والحذف والفلاتر.
- Canvas لا يختبر النقر والإحداثيات وإعادة الجولة.
- لا توجد اختبارات callbacks ذات معامل واحد لكل نوع حدث.
- لا توجد اختبارات ضغط أحداث متكرر أو queue ordering.
- لا توجد جولة كاملة في WebApp لكل مشروع.
- ZIP يُختبر بfixture واحد، لا بالمشروعات المسجلة كلها.
- PWA وWindows غير متحققين فعليًا.
- لا توجد Unit tests مباشرة لـ`workerSource.dispatchEvent` أو arity.
- قائمة المكونات المتوقعة في اختبار manifest لا تغطي جميع المكونات المعلنة مثل
  `Chart` و`Timer` و`Audio` و`Guide`.

## دين تقني في مسار التعلم

- خطة لعبة التخمين القديمة ما زالت تشير إلى `appkit`.
- حلقة توليد الخطط العامة تستبدل الخطة المخصصة بخطة عامة متكررة.
- المحرر يحمّل `starterCode` الكامل بينما لوحة الخطوات تعرض ثلاث خطوات عامة؛
  لذلك لا يوجد تطابق حقيقي بين «ابنِ المشروع خطوة بخطوة» والكود المعروض.

## خطة الإصلاح

### P0 — قبل أي Prototype

1. تعريف Event payload contract لكل حدث.
2. إصلاح استدعاء callback ذي صفر أو معامل واحد بصورة موثوقة.
3. إضافة Unit test لكل نوع حدث.
4. إضافة اختبار Timer لعدة نبضات مع pause/reset.
5. إضافة اختبار Slider يسحب المنزلق ويتحقق من RGB/HEX.
6. منع عرض المشاريع `blocked` في Gallery الطالب.
7. إظهار حالة المشروع وسبب الحجب للمعلم.

### P1

1. ضمان ترتيب event queue وعدم إسقاط آخر snapshot.
2. Debounce/Throttle للأحداث عالية التردد مثل Slider وpointermove.
3. اختبار destroy/restart أثناء حدث قائم.
4. رسائل أخطاء تحتوي اسم المشروع والحدث والسطر الحقيقي.
5. Telemetry محلية غير حساسة لنتائج QA في بيئة الاختبار.

## مصفوفة قبول Callback

يجب اختبار كل حدث مع:

- callback بلا معامل.
- callback بمعامل.
- تحديث مكوّن واحد وعدة مكونات.
- خطأ داخل callback.
- حدثان متتاليان بسرعة.
- إعادة التشغيل بعد الخطأ.
- التشغيل داخل المنصة وWebApp وZIP.

## شرط رفع الحجب

لا يُرفع `blocked` عن المؤقت أو الألوان إلا بعد:

- نجاح Unit callback contract.
- نجاح Integration للمسار الأساسي والخاطئ وreset.
- نجاح WebApp المباشر.
- نجاح ZIP المستضاف محليًا.
- عدم ظهور أي Error banner في جولة كاملة.
