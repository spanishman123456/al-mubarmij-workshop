# معيار جودة المشروعات النهائية لطلاب موهبة

**الحالة:** معيار اعتماد ملزم قبل إضافة أي مشروع إلى قسم «المشروعات النهائية المتقدمة»  
**تاريخ الإصدار:** 2026-07-13

## القرار التنفيذي

> تم إيقاف اعتبار التطبيقات البسيطة الحالية مشروعات نهائية، وتصنيفها كتدريبات مصغرة، كما تم إعداد معيار جديد لمشروعات موهبة يعتمد على الأصالة والتحدي العقلي والمنطق البرمجي والتفاعل والتصميم البصري والاستقرار وقابلية التصدير. ولن يتم اعتماد أي مشروع نهائي جديد قبل تجاوزه 85 من 100 في Rubric الجودة.

## التصنيف الجديد

### تمارين ومشروعات تدريبية مصغرة

تُستخدم لتعليم مكوّن أو مفهوم محدد، مثل `Button` و`Input` و`Slider` و`Timer` وCallbacks والتحقق من المدخلات وتحديث الحالة. وتشمل القائمة الحالية:

- لعبة تخمين الرقم
- آلة حاسبة
- نموذج تسجيل
- قائمة مهام
- اختبار قصير
- مؤقت
- لوحة بيانات بسيطة
- تطبيق ألوان
- لعبة Canvas المصغرة
- محاكاة البحث الخطي
- تشفير قيصر
- لعبة تعليمية للحساب
- محول أنظمة العد

تبقى هذه الأنشطة متاحة في قسم التدريب بعد اجتياز اختبارات Runtime، ولا تُعرض بوصفها منتجات نهائية أو مشروعات متقدمة.

### المشروعات النهائية المتقدمة

لا يدخل المشروع هذا القسم إلا إذا:

1. يعالج مشكلة أو محاكاة أو قرارًا أو تحديًا ذا معنى.
2. يتطلب التفكير والتخطيط والمقارنة أو التحسين، وليس ضغطة واحدة.
3. يستخدم منطقًا برمجيًا مركبًا مناسبًا لعمر الطالب.
4. يحتوي على شاشة بداية، مساحة عمل، تغذية راجعة، نتيجة، وإعادة تجربة.
5. يمتلك هوية وتخطيطًا مستقلين عن بقية المشروعات.
6. يعمل دون أخطاء Runtime في جميع مساراته الأساسية والخاطئة.
7. ينجح في المعاينة وWebApp وZIP، وبقية أهداف التصدير عند توفرها.
8. ينجح على Desktop وTablet وMobile دون قص أو تمرير متداخل.
9. يحصل على 85/100 أو أكثر في Rubric المعتمد.

## حالات المشروع

- `draft`: فكرة أو نموذج أولي غير متاح للطلاب.
- `qa`: مكتمل وظيفيًا ويخضع للاختبارات.
- `blocked`: يحتوي خطأ Runtime أو فشل تصدير أو مشكلة وصول حرجة؛ لا يظهر للطلاب.
- `training`: تدريب مصغر صالح للتعلم، لكنه ليس مشروعًا نهائيًا.
- `final`: اجتاز الاختبارات وRubric بدرجة 85 أو أكثر.

لا يكفي ظهور الواجهة لنقل المشروع إلى `qa` أو `final`.

## بنية التجربة النهائية

يجب أن تتضمن التجربة، وفق طبيعة المشروع:

- Welcome / Briefing: القصة، المهمة، القيود، ومعيار النجاح.
- Onboarding: شرح تفاعلي قصير قابل للتخطي.
- Main Workspace: مساحة عمل كاملة وليست بطاقة صغيرة في المنتصف.
- States: بداية، تشغيل، نجاح جزئي، تحذير، خطأ، نهاية.
- Progress: مراحل أو جولات أو مؤشرات أداء.
- Result Analysis: نتيجة مفهومة تشرح أثر القرارات.
- Replay: سيناريو جديد أو صعوبة مختلفة أو هدف قابل للتحسين.
- Accessibility: لوحة مفاتيح، لمس، تركيز واضح، RTL/LTR.

## معيار المنطق البرمجي

يجب أن يستخدم المشروع النهائي مجموعة مترابطة من العناصر التالية، لا مجرد وجودها الشكلي:

- شروط وحلقات ودوال.
- قوائم وقواميس ونمذجة حالة.
- خوارزمية بحث أو فرز أو تخصيص أو تحسين.
- تحقق من المدخلات ومعالجة حالات الحواف.
- نظام درجات أو موارد أو مؤشرات متعددة.
- مراحل أو انتقالات حالة.
- مؤقتات أو عشوائية مضبوطة عند الحاجة.
- سجل أحداث أو تفسير للقرارات.

## بوابات الجودة

### بوابة الفكرة

- المشكلة واضحة ويمكن لشخص خارجي فهمها خلال 30 ثانية.
- توجد قرارات متعددة ذات نتائج مختلفة.
- يمكن إعادة التجربة وتحسين النتيجة.

### بوابة Runtime

- كل Callback مختبر مباشرة.
- عقدة القيمة للأحداث موحدة وموثقة.
- المؤقتات وCanvas وإعادة التشغيل لا تنتج أخطاء.
- المشروع ذو خطأ Runtime يُوسم `blocked` آليًا.

### بوابة التصميم

- هوية بصرية مستقلة وتخطيط مناسب للمهمة.
- لا يعتمد على قالب Card مركزي موحد.
- لا يوجد تمرير مزدوج أو عناصر مقطوعة.
- جميع الحالات المرئية مصممة، بما فيها loading/success/warning/danger/disabled.

### بوابة التعليم

- الطالب يرى المهمة والمراحل والتلميحات والاختبارات، لا الحل الكامل.
- المعلم يرى المعمارية والحل النموذجي واختبارات القبول والأخطاء الشائعة.
- يجب فصل `studentStarterCode` عن `teacherSolutionCode`. الوضع الحالي يحمّل
  التطبيق الكامل من `SKUI_DEMO_APPS` للطرفين، ولذلك لا يحقق هذه البوابة بعد.
- يجب أن يطابق كود كل مرحلة الاختبار والتلميح الخاصين بها، وألا تستبدل الخطة
  المخصصة بخطة عامة أو مرجع قديم إلى `appkit`.

### بوابة التصدير

- نفس runtime وevent bridge وstyles وassets مستخدمة في المنصة والحزمة المصدرة.
- WebApp المباشر وZIP ينجحان في السيناريو الأساسي والخاطئ.
- PWA وWindows لا يُعلنان كمدعومين قبل تحقق فعلي.

## سياسة الإطلاق

1. Proposal مع Rubric تقديري.
2. Prototype غير ظاهر للطلاب.
3. مراجعة فكرة وتصميم.
4. تنفيذ واختبارات Unit.
5. Integration وPlaywright عبر المقاسات.
6. اختبار التصدير.
7. تقييم لجنة داخلية.
8. اعتماد `final` فقط عند درجة 85+ وعدم وجود أي بند حرج فاشل.
